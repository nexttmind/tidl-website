Webhooks — PrescribeRx API\nWebhooks Guide\n← Back to API reference\nWebhooks let your app receive real-time notifications for events that happen in PrescribeRx —
            an encounter is created, an order ships, lab results arrive, a subscription renews. Subscribe to
            the events you care about and we'll\nPOST\na signed JSON payload to your URL when each
            event fires. This page covers the 35 subscribable events,
            how to set up a subscription, signature verification, and how to handle failures.\nTwo ways to manage webhook subscriptions:\nUI\n— Sales orgs and clients can self-serve from their portal:\n/sales-organization/integrations/webhooks\nor\n/client/settings/webhooks\n. Return\n2xx\nwithin 30 seconds — anything else is treated as a failure and triggers retries.\n2\nSubscribe via UI or API\nUI:\nGo to your portal's webhooks page, click "Add subscription", paste the
                URL, pick events, save. The signing secret is shown once — copy it.\nAPI:\ncurl\n-X POST\n"https://demo.prescribe-rx.com/api/v1/webhooks"\n\
  -H\n"Authorization: Bearer YOUR_TOKEN"\n\
  -H\n"Content-Type: application/json"\n\
  -d\n'{
    "url": "https://your-app.com/webhooks/prescriberx",
    "events": ["encounter.prescribed", "order.placed", "fulfillment.shipped"],
    "is_active": true
  }'\nResponse includes\nid\n,\nsigning_secret\n(shown once — store it
                securely), and the events you subscribed to.\n3\nVerify the signature on every delivery\nEvery webhook arrives with an\nX-PrescribeRx-Signature\nheader. The value
                is\nsha256=<hex>\nwhere\n<hex>\nis the lowercase hex
                digest of\nHMAC-SHA256(raw_request_body, signing_secret)\n. Compute it on
                your side using the raw request body bytes (not parsed JSON) and the signing secret
                you copied at subscription creation. Reject deliveries that don't match.\nFormat.\nBoth production deliveries and test deliveries (from\nPOST /api/v1/webhooks/{id}/test\n) send the same shape:\nX-PrescribeRx-Signature: sha256=a1b2c3...\n. Strip the\nsha256=\nprefix before comparing the remainder against your computed
                    HMAC. The prefix exists for forward compatibility (future algorithms will use
                    the same envelope, e.g.\nsha512=\n).\n// PHP\n$received\n=\n$_SERVER\n[\n'HTTP_X_PRESCRIBERX_SIGNATURE'\n] ??\n''\n;\n$received\n=\nstr_starts_with\n(\n$received\n,\n'sha256='\n) ?\nsubstr\n(\n$received\n,\n7\n) :\n$received\n;\n$expected\n=\nhash_hmac\n(\n'sha256'\n,\n$rawBody\n,\n$signingSecret\n);\nif\n(!\nhash_equals\n(\n$expected\n,\n$received\n)) {\nhttp_response_code\n(\n401\n);\nexit\n;

                attempt 1,\n~100s\n(~1.7 min) after attempt 2, then no further attempts.
                Each attempt has a\n30-second timeout\n.\nAfter\n50 consecutive failures\nacross deliveries the subscription
                is auto-disabled — the UI shows a banner and you'll receive an email; re-enable via\nPOST /api/v1/webhooks/{id}/re-enable\nafter fixing your endpoint.\nTreat each delivery as\nat-least-once\n: include an idempotency check
                keyed on the\nwebhook_id\nfield (a UUID generated per delivery, also sent
                in the\nX-Webhook-ID\nheader).\nSubscription management endpoints\nVerb\nPath\nPurpose\nRequired ability\nGET\n/api/v1/webhooks/event-types\nList subscribable event types\nwebhook:read\nGET\n/api/v1/webhooks\nList your subscriptions\nwebhook:read\nPOST\n/api/v1/webhooks\nCreate a subscription\nwebhook:create\nGET\n/api/v1/webhooks/{id}\nGet one subscription\nwebhook:read\nPUT\n/api/v1/webhooks/{id}\nUpdate URL / events / active flag\nwebhook:update\nDELETE\n/api/v1/webhooks/{id}\nDelete a subscription\nwebhook:delete\nPOST\n/api/v1/webhooks/{id}/rotate-secret\nRoll the signing secret\nwebhook:update\nPOST\n/api/v1/webhooks/{id}/re-enable\nRe-enable an auto-disabled subscription\nwebhook:update\nPOST\n/api/v1/webhooks/{id}/test\nTrigger a webhook.test delivery\nwebhook:update\nGET\n/api/v1/webhooks/{id}/delivery-logs\nRecent delivery attempts (request/response)\nwebhook:read\nSample payload shape\nEvery delivery follows the same envelope.
