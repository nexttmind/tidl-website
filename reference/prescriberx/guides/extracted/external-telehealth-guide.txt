External Telehealth API — PrescribeRx\nExternal Telehealth API\n← Back to API reference\n← Back to API reference\nIntegration surface for 3rd-party telehealth companies that prescribe in their
            own e-Rx system and route fulfillment through PrescribeRx. Two endpoints to
            register prescribers + look them up, one to submit fully-formed prescription
            orders. Webhook subscribers receive status callbacks back as orders progress.\nAt a glance\nEndpoint\nPurpose\nAbility\nPOST /api/v1/external-telehealth/providers\nRegister prescriber (idempotent on NPI+client)\nexternal-telehealth:providers:write\nGET  /api/v1/external-telehealth/providers/{npi}\nLook up provider(s) — poll for admin approval state\nexternal-telehealth:providers:read\nPOST /api/v1/external-telehealth/orders\nSubmit a fully-formed prescription order\nexternal-telehealth:orders:write\nThe interactive Try-It client for all three endpoints is on the main\nAPI reference\n, under the\nExternalTelehealth\ntag.\n1 — How tenancy works\nThe effective sales-org id resolves from either side of the user identity graph:\neffective_sales_org_id = user.sales_organization_id
                       ?? user.client.sales_organization_id\nBoth token shapes are supported:\nToken shape\nWhat it can do\nSales-org\nSubmit orders / register providers against any\nclient_id\nunder its sales org. Use this when a 3rd-party telehealth company serves multiple of your clinics.\nClient\nEffectively pinned to its own\nclient_id\n— the only payload value that resolves to its sales org's client tree. Use this when a single clinic / practice integrates directly.\nCross-tenant\nclient_id\n→\nHTTP 403\nwith:\n"API user must belong to a sales organization (directly, or via their client)."\n2 — Onboarding (one-time)\nYour account rep creates either a SalesOrganization (multi-clinic integrator) or a Client (single-clinic) for you, plus an API user.\nThe rep issues a Sanctum bearer token for that API user with these abilities, which are granted manually (NOT in any default ability set):\nexternal-telehealth:providers:write\nexternal-telehealth:providers:read\nexternal-telehealth:orders:write\nWebhook abilities (\nwebhook:*\n) are already in the default set for both sales-org and client user types.\nSave the token securely — it's not retrievable from our side once issued.\nTest against\nhttps://demo.prescribe-rx.com\nfirst. Production is\nhttps://prescribe-rx.com\nwith identical shapes.\nPayments & merchant accounts (one-time — required for on-system billing)\nIf you process the patient's payment on\nyour own\ngateway
            (outside PrescribeRx) but want PrescribeRx to handle any\nfuture\nbilling on that card — subscription rebills, refills, deferred captures,
            refunds — you must\nadd that merchant account inside PrescribeRx first\n.
            Without it, the transaction you report is recorded audit-only (no merchant
            attached) and any card you send is stored display-only (not chargeable).\nIn the PrescribeRx portal as your sales org, go to\nSettings → Payments → Merchant Accounts\nand add an
                account for the\nsame gateway\nyou charge on
                (\nauthorize_net\n,\nstripe\n,\nnmi\n, or\nsquare\n), with that gateway's credentials. Mark it active.\nCopy its\nmerchant account UUID\n.\nOn each intake you submit, include the\npayment\nblock with\nmode: "reference_captured"\n(or\nreference_preauth\n),
                your\nmerchant_account_id\n, the\ntransaction\ndetails (id + amount), and — to make the card rechargeable — the\ndurable\ncard_token\nrefs from your gateway's
                vault (e.g. Stripe\ncustomer_id\n+\npayment_method_id\n;
                Auth.Net\ncustomer_profile_id\n+\npayment_profile_id\n;
                NMI\ncustomer_vault_id\n; Square\ncustomer_id\n+\ncard_id\n). See the\npayment\nblock on\nPOST /telehealth/intake/unified\nin the API reference for the
                full field-by-field contract and a complete example.\nThe merchant's gateway must match your\ncard_token\nrefs and the
            account must belong to your org — PrescribeRx validates both and, on a
            mismatch, records the transaction without a merchant rather than charging the
            wrong account. Collected payment in person / out of band with no electronic
            record? Omit\npayment\nor use\nmode: "prepaid"\n.\n3 — Register a provider\nEvery prescriber must exist + be admin-approved before any order can reference them by NPI.\ncURL\ncurl -X POST https://demo.prescribe-rx.com/api/v1/external-telehealth/providers \
