API Token Types & Abilities — PrescribeRx\nAPI Token Types & Abilities\n← Back to API reference\nEvery PrescribeRx API request must carry a Sanctum bearer token. The token's\ntype\ndetermines which endpoints it can hit, the data scope (single tenant vs. hierarchy), and which
            payload fields are honoured. This page lists the four production token types, how to provision each,
            and what they're allowed to do.\nHow to authenticate:\nAll tokens are passed as\nAuthorization: Bearer {token}\n. Tokens are generated by an
            authenticated user (or admin) and inherit that user's\nUserType\n.
            Token abilities are computed from\nTokenAbility::forUserType()\nat
            issue time — see "Updating abilities" at the bottom for what happens when the
            mapping changes.\n🏢 Sales Organization Token\nUserType::2\nWho uses it\nA sales organization integrating PrescribeRx into their own product (white-label, partner site, or back-office portal).\nHow to provision\nProvisioned by the sales-org owner from /sales-organization/api-tokens, OR by an admin attaching a token to any user with UserType::SALESORGANIZATION.\nData scope\nTenant-scoped to the org and all its hierarchical descendants (child orgs + clients + their patients/encounters/orders). Cannot read other orgs.\nCommon use cases\nSubmitting telehealth intakes from a partner-branded site\nQuerying products + packages available to the org\nReading orders + encounters across the org hierarchy\nManaging webhook subscriptions for org-wide events\nToken abilities (26)\nsales-org:read\nsales-org:update\nclient:read\nclient:create\nclient:pricing:write\norder:read\norder:create\norder:update\nproduct:read\npatient:read\npatient:create\npatient:update\npatient:issue-token\nprescription:read\ntelehealth:read\ntelehealth:submit\nencounter:read\nencounter:create\nencounter:update\nwebhook:read\nwebhook:create\nwebhook:update\nwebhook:delete\nscheduling:read\nscheduling:write\nlab:read\nExample: cURL request\n# Sales Organization Token — submitting a unified intake\ncurl\n-X POST\n"https://demo.prescribe-rx.com/api/v1/telehealth/intake/unified"\n\
